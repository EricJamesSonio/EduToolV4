# Learning the Better Way of Using AI Agents

## [ Ticket ]

The ticket is the **source of truth** for what needs to be accomplished.

---

## [ AI Agent ] — Orchestrator

The Orchestrator is responsible for managing the entire engineering workflow.

### Planning

- Analyze the ticket and understand the requirements.
- Analyze the existing codebase.
  - Use Graphify or other code-search/retrieval tools when needed.
- Identify the affected modules, files, dependencies, and existing architecture.
- Define the **acceptance criteria** for the ticket.
- Define the **test strategy** based on the acceptance criteria.
- Define what the final implementation should achieve.
- Create an implementation strategy.
- Split the work into small, workable, independent, and safe tasks.
- Determine which subagent should handle each task.
- Establish the order and dependencies between tasks.

### Delegation

Assign the appropriate work to specialized subagents:

- **Developer Agent** → Implementation
- **Test Agent** → Tests
- **Reviewer Agent** → Review

The Orchestrator should provide each subagent with the necessary context, requirements, constraints, and expected output.

### Verification

The Orchestrator controls the verification process.

After implementation:

- Run the project's automated tests.
- Run relevant integration/end-to-end tests when necessary.
- Run linting.
- Run type checking when applicable.
- Run the build.
- Verify that the acceptance criteria are satisfied.
- Send actual tool/test results back to the appropriate subagent when something fails.

The AI should **not simply decide that the implementation is successful**.

Actual test, build, lint, and tool results should provide objective evidence.

### Loop Engineering

If verification fails:

```text
Implementation
      ↓
Run Tests
      ↓
FAIL
      ↓
Analyze Failure
      ↓
Developer Agent Fixes
      ↓
Run Tests Again
```
