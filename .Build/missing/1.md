================================================================================
  MODULE 1: submission
================================================================================

PURPOSE
  Handles student-side assessment interaction.
  Educator uses this to view, grade essays, and manage student attempts.

FILES TO CREATE
  src/modules/submission/
  ├─ submission.controller.ts
  ├─ submission.module.ts
  ├─ submission.repository.ts
  ├─ submission.service.ts
  ├─ dto/
  │   └─ submission.dto.ts
  └─ entity/
      └─ submission.entity.ts

ENDPOINTS (student-facing)
  POST   /assessments/:assessmentId/submit        — start or resume attempt
  PATCH  /assessments/:assessmentId/submit/save   — auto-save draft answers
  POST   /assessments/:assessmentId/submit/finish — final submission + auto-grade

ENDPOINTS (educator-facing — viewing only, grading already in assessment module)
  GET    /assessments/:assessmentId/submissions/:submissionId/answers
         — view a student's submitted answers

WHAT TO BUILD
  - Start attempt: create Submission with status=draft if none exists,
    resume if draft already exists (one active attempt rule)
  - Save answers: upsert SubmissionAnswer records per question
  - Finish: mark status=submitted, auto-grade non-essay questions
    by comparing answer to correct_answer on Question,
    set score = correct count, set submitted_at = now()
  - Auto-close drafts when end_date passes (handled by cron later)
  - Get answers: educator views submitted answers per student

SCHEMA ADDITIONS NEEDED
  None — Submission and SubmissionAnswer already exist in schema.

DEPENDENCIES
  - AssessmentModule (exported AssessmentRepository)
  - NotificationModule
  - AuditLogModule


================================================================================
  MODULE 2: attendance
================================================================================

PURPOSE
  Tracks per-session attendance for each class.
  Sessions are generated from class schedules.
  Holiday/No Class Day sessions are automatically skipped.

FILES TO CREATE
  src/modules/attendance/
  ├─ attendance.controller.ts
  ├─ attendance.module.ts
  ├─ attendance.repository.ts
  ├─ attendance.service.ts
  ├─ dto/
  │   └─ attendance.dto.ts
  └─ entity/
      └─ attendance.entity.ts

ENDPOINTS
  POST   /classes/:classId/attendance/sessions
         — generate sessions for a week (or full semester)
  GET    /classes/:classId/attendance/sessions
         — list all sessions, grouped by week
  GET    /classes/:classId/attendance/sessions/:sessionId
         — get one session + all student records
  POST   /classes/:classId/attendance/sessions/:sessionId/records
         — bulk set attendance for all students in a session
  PATCH  /classes/:classId/attendance/sessions/:sessionId/records/:recordId
         — override a single student's attendance status

WHAT TO BUILD
  - Session generation: create AttendanceSession records
    from ClassSchedule weekday+time, skip dates that fall on
    AcademicCalendar holiday or no_class_day events
  - Week numbering: sequential, no gaps even when sessions skipped
  - Records: one AttendanceRecord per student per session
    Status options: present | absent | late | excused
  - Auto-attendance from assessment submission:
    when a submission is marked submitted on a session date,
    auto-mark that student present for that session
  - Educator can override any record before grade lock

SCHEMA ADDITIONS NEEDED
  None — AttendanceSession and AttendanceRecord already exist.

DEPENDENCIES
  - ClassModule (ClassRepository for schedules + enrollment)
  - AcademicCalendarModule (to check holiday/no_class_day dates)
  - AuditLogModule


================================================================================
  MODULE 3: grade (educator-facing extension)
================================================================================

PURPOSE
  Educator views and manages computed grades per term.
  Grade computation pulls scores from assessments + manual rubric entries.
  This extends the existing grade module — add controller + expand service.

FILES TO UPDATE
  src/modules/grade/
  ├─ grade.controller.ts        ← CREATE (doesn't exist yet)
  ├─ grade.module.ts            ← UPDATE (add controller)
  ├─ grade.repository.ts        ← UPDATE (add more queries)
  ├─ grade.service.ts           ← UPDATE (add grade computation logic)
  ├─ dto/
  │   └─ grade.dto.ts           ← CREATE
  └─ entity/
      └─ grade.entity.ts        ← CREATE

ENDPOINTS
  GET    /classes/:classId/grades
         — get all student grades for the class, grouped by term
  GET    /classes/:classId/grades/:termId
         — get per-student grades for a specific term
  POST   /classes/:classId/grades/:termId/compute
         — trigger grade computation for all students in a term
           pulls submission scores + manual rubric scores,
           applies rubric weights, saves to Grade table
  PATCH  /classes/:classId/grades/:termId/students/:studentId/manual
         — educator sets manual score for a rubric category
           (attendance summary, behavior, recitation, participation)

WHAT TO BUILD
  - Grade computation logic:
      For each enrolled student:
        1. Pull all submissions for assessments in this term+class
        2. Group by rubric category (activity, quiz, exam, etc.)
        3. Apply rubric weights from class rubric
        4. Add manual category scores (attendance, behavior, etc.)
        5. Compute weighted total = final_score
        6. Look up grading scale to get final_grade string
        7. Upsert into Grade table
  - Grade display modes:
      Default view: individual assessment scores per student
      Clean view: aggregated by rubric category per student
  - Manual score entry per rubric category per student

SCHEMA ADDITIONS NEEDED
  Add ManualScore model to store per-student per-category manual entries:

  model ManualScore {
    id          String   @id @default(uuid())
    org_id      String
    class_id    String
    student_id  String
    term_id     String
    category    String   // matches rubric category name
    score       Float
    updated_at  DateTime @updatedAt

    @@unique([org_id, class_id, student_id, term_id, category])
  }

  Run: npx prisma migrate dev --name add_manual_score

DEPENDENCIES
  - AssessmentModule (AssessmentRepository for submission scores)
  - ClassModule (ClassRepository for enrollments + rubric)
  - GradingScaleModule (to resolve final_grade from score)
  - AuditLogModule
