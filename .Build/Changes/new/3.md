Locked Design Decisions
1. Program scoping — minor subject belongs to exactly one program. Can only be shared to courses/strands/levels within that same program. Cross-program sharing is not allowed.
2. Class creation — when building a class, the subject dropdown shows both majors AND minors that are shared to the selected course/strand/level. Minor subjects are first-class subjects for class creation.
3. Prerequisites — same as majors, admin has full freedom. No special rules.
4. Same subject different program — separate rows. "Oral Communication" in SHS and "Oral Communication" in College are two different subject rows with the same name but different program_id. Cleaner for the user.
5. Edit reflects everywhere — editing a minor subject (name, term, educator) updates the single row, all sharings see the change automatically since they point to the same row.
6. K-12 minors — subject_type: 'minor' is just a label/flag. Admin marks MAPEH Grade 1 as minor if they want. No forced sharing required. Minor in K-12 just means "this subject is categorized as minor" — admin decides everything else freely.

Answer 6 changes one thing — level_id should stay optional on Subject because:

Minor subjects in College/SHS don't need a level_id (they're scoped by program_id + sharings)
Minor subjects in K-12 that the admin just flags as minor with no sharing also don't strictly need it tied to a level
