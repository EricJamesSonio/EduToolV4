EDUTOOL SYSTEM DOCUMENTATION
=================================================

SYSTEM OVERVIEW
-------------------------------------------------
EduTool is an academic management system used by
three main user roles:

1. Admin
2. Educators
3. Students

The system manages:

- Departments
- Semesters
- Classes
- Schedules
- Lessons
- Assessments
- Grades
- Meetings

Admins configure the academic structure of the
school while educators manage teaching activities.



=================================================
USER ROLES
=================================================

ADMIN
-------------------------------------------------
Represents the school administrator or head.

Responsibilities:

- Manage departments
- Manage semesters (global templates)
- Create classes
- Assign educators
- Manage schedules
- Create level sections
- Configure academic structure

Admins can only manage their own school and
cannot access other schools.



EDUCATORS
-------------------------------------------------
Teachers assigned to classes.

Responsibilities:

- Manage lessons
- Generate assessments
- Manage grades
- Conduct meetings
- Track student performance



STUDENTS
-------------------------------------------------
Students participate in learning activities.

Responsibilities:

- Join classes
- View lessons
- Take assessments
- Attend meetings
- View grades

=================================================
SEMESTER SETTINGS
=================================================

Semesters are reusable templates that define
academic time ranges.

These are **NOT directly attached to departments**.
Instead, departments **select a semester setting**.

This allows different departments to follow
different academic calendars.

Example:

Semester Template A

1st Semester
Start Date: June 1
End Date: October 30

2nd Semester
Start Date: November 15
End Date: March 30


Semester Template B

1st Semester
Start Date: August 10
End Date: December 20

2nd Semester
Start Date: January 10
End Date: May 15

=================================================
SCHEDULE MANAGEMENT
=================================================

Schedules are automatically generated based on
created classes.

Each year level has its own schedule view.

However, schedule validation checks **ALL year
levels within the department**.



-------------------------------------------------
SCHEDULE CONFLICT VALIDATION
-------------------------------------------------

The system checks two major conflicts:



1. TIME OVERLAP
Two subjects cannot occupy the same time slot
within the same year level.



2. EDUCATOR CONFLICT
An educator cannot teach two classes at the
same time across any year level.

Example Conflict:

1st Year
Monday
7:00 AM
Data Structure
Eric James

3rd Year
Monday
7:00 AM
Parallel Computing
Eric James

This is NOT allowed.



-------------------------------------------------
CROSS-YEAR VALIDATION
-------------------------------------------------

The system checks schedules across:

- 1st Year
- 2nd Year
- 3rd Year
- 4th Year

Because some educators teach multiple year levels.

The validator scans **all schedules inside the
department** to prevent conflicts.

-------------------------------------------------
CLASS CAPACITY SETTINGS
-------------------------------------------------

The Admin can configure class capacity in two ways:


1. LIMITED CAPACITY

The Admin sets a maximum number of students
allowed to enroll in the class.

Example

Capacity: 40 students

Once the class reaches this limit,
no more students can be added unless
the capacity is increased.



2. UNLIMITED CAPACITY

The Admin can set the class capacity to
"Unlimited".

This means there is no maximum limit
for the number of students that can join
the class.

=================================================
STUDENT MANAGEMENT
=================================================

Students create their own accounts.

Admins do not manually create student accounts.

When adding students to classes, the system
filters students automatically.

Filtering Conditions:

- Course
- Year Level

Example

Class: BSCS 1st Year

Only students with:

Course = BSCS
Year = 1

will appear in the selection list.

-------------------------------------------------
LESSON DETAIL REQUIREMENTS
-------------------------------------------------

Lesson detail must contain at least:

10 words minimum.

Reason:

The system uses lesson details for
AI-based concept extraction.



-------------------------------------------------
CONCEPT EXTRACTION
-------------------------------------------------

When lesson detail exists:

The system automatically extracts learning
concepts.

This process runs in the background and
continues even if the user navigates away.

Users receive a notification when the
extraction process is completed.

-------------------------------------------------
VALIDATION RULES
-------------------------------------------------

Item count must not exceed the maximum
concept capacity.

Sections must contain enough questions
to support the requested item count.



-------------------------------------------------

-------------------------------------------------

is complete.

The process can also be cancelled by the user.

=================================================

Grades automatically recompute when:

- Assessment submitted
