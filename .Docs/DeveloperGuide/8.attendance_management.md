# DEV-08 — Attendance Management
**EduTool Developer Guide**
> Covers: Attendance record generation, auto-attendance from assessments, manual entry, weekly view, calendar event integration.

---

## 1. Overview

Attendance in EduTool is tracked per **class session** — not per calendar day. Sessions are defined by the class's scheduled weekdays (see DEV-05). The educator sees attendance organized by week, can set statuses manually, and benefits from automatic attendance when students submit assessments on a session day.

---

## 2. Data Model

### 2.1 AttendanceRecord

```
AttendanceRecord
  id              UUID, primary key
  class_id        FK → Class
  session_id      FK → ClassSession
  student_id      FK → Student
  status          enum (PRESENT | ABSENT | LATE | EXCUSED | NULL)
                  -- NULL = no status yet assigned
  source          enum (AUTO | MANUAL)
                  -- AUTO = set by assessment submission
                  -- MANUAL = set by educator
  set_by          FK → Educator, nullable
  set_at          timestamp, nullable
  created_at      timestamp
```

### 2.2 Rules

- One `AttendanceRecord` per `(session_id, student_id)` pair.
- Sessions on `HOLIDAY` or `NO_CLASS_DAY` calendar events have **no records** — they are not created at all.
- A record with `status = NULL` means no attendance has been marked yet for that session.
- Educator can override any record (including AUTO-set ones) by setting `source = MANUAL`.

---

## 3. Attendance Record Creation

### 3.1 When Records Are Created

Attendance records are created for each enrolled student for each valid session when:
- A new student is enrolled in a class (records created for all future sessions)
- A new class session is generated (records created for all currently enrolled students)

```
FUNCTION createAttendanceRecordsForSession(session_id):
  session = getClassSession(session_id)
  IF session.is_skipped:
    RETURN  -- do not create records for skipped sessions

  enrolled_students = getActiveEnrollments(session.class_id)
  FOR each student in enrolled_students:
    existing = getAttendanceRecord(session_id, student.id)
    IF existing IS NULL:
      CREATE AttendanceRecord {
        class_id: session.class_id,
        session_id,
        student_id: student.id,
        status: NULL,
        source: MANUAL
      }

FUNCTION createAttendanceRecordsForStudent(student_id, class_id):
  -- Called when a student is newly enrolled mid-semester
  future_sessions = getClassSessions(class_id,
                      where: date >= today AND is_skipped = false)
  FOR each session in future_sessions:
    existing = getAttendanceRecord(session.id, student_id)
    IF existing IS NULL:
      CREATE AttendanceRecord {
        class_id,
        session_id: session.id,
        student_id,
        status: NULL,
        source: MANUAL
      }
```

### 3.2 Late Enrollment — Past Sessions

When a student is enrolled mid-semester, **past sessions** do not get attendance records automatically. The educator handles past assessments (status: NULL / Exempted / Custom) but attendance for past sessions is left unrecorded unless educator manually adds them.

## 4. Auto-Attendance from Assessment Submission

When a student submits an assessment (`StudentAssessment.status` becomes `SUBMITTED`):

```
FUNCTION autoMarkAttendance(student_id, assessment_id):
  assessment = getAssessment(assessment_id)
  submitted_at = AssessmentAttempt.submitted_at (just set)

  -- Find the class session for the day the student submitted
  session = getClassSession(
    class_id: assessment.class_id,
    date: DATE(submitted_at)  -- the calendar date of submission
  )

  IF session IS NULL OR session.is_skipped:
    RETURN  -- no session on this date, no attendance to mark

  record = getAttendanceRecord(session.id, student_id)
  IF record IS NULL:
    RETURN  -- no record exists (student may have been enrolled after sessions generated)

  IF record.source = MANUAL AND record.status != NULL:
    RETURN  -- educator has already manually set this — do not override

  -- Mark present
  UPDATE AttendanceRecord SET
    status = PRESENT,
    source = AUTO,
    set_at = now()
  WHERE id = record.id
```

**Rules:**
- Auto-attendance only sets `PRESENT`. It never sets Absent, Late, or Excused.
- Auto-attendance does NOT override a manually set status.
- If the educator has already marked the student (any status), auto-attendance is skipped.

## 5. Manual Attendance Entry

Educator can set or override any attendance record at any time before grades are locked.

```
FUNCTION setAttendance(session_id, student_id, status, educator_id):

  -- Validate grade lock
  class = getClassFromSession(session_id)
  IF class.grades_locked:
    RETURN error: "Grades are locked. Attendance cannot be changed."

  record = getAttendanceRecord(session_id, student_id)
  IF record IS NULL:
    RETURN error: "No attendance record found for this student and session."

  UPDATE AttendanceRecord SET
    status = status,  -- PRESENT | ABSENT | LATE | EXCUSED | NULL
    source = MANUAL,
    set_by = educator_id,
    set_at = now()
  WHERE id = record.id
```

Valid statuses educator can set:
- `PRESENT`
- `ABSENT`
- `LATE`
- `EXCUSED`
- `NULL` (clear/reset — remove any prior mark)

## 6. Weekly Attendance View

### 6.1 Layout

The attendance view mirrors the class's week structure from DEV-05.

```
Week 1
  └── Session 1  (Mon, Jan 13)
        Student A: Present (auto)
        Student B: Absent
        Student C: NULL (not yet marked)

Week 2
  └── Session 2.1  (Mon, Jan 20)
  └── Session 2.2  (Wed, Jan 22)
        ...
```

Single-weekday classes show one session per week. Multi-weekday classes show sub-sessions per their label.

### 6.2 API Response Shape

```
GET /classes/{class_id}/attendance

Response:
{
  weeks: [
    {
      week_number: 1,
      sessions: [
        {
          session_id: "...",
          week_label: "Week 1",
          date: "2025-01-13",
          weekday: "MON",
          students: [
            {
              student_id: "...",
              full_name: "...",
              attendance_status: "PRESENT",
              source: "AUTO"
            },
            ...
          ]
        }
      ]
    },
    ...
  ]
}
```

### 6.3 Filtering

Educator can filter the weekly view by:
- Student name or ID
- Week range
- Attendance status

## 7. Attendance and Grade Computation

The rubric may include an `Attendance` category (of type `MANUAL_ENTRY`). When it does:
- The educator manually inputs an attendance summary **score** per student into the grade sheet.
- The raw session-by-session records are for the educator's reference — they do **not** auto-compute into a grade.
- This is intentional. Different schools compute attendance grades differently.

> Note: A future version may support auto-calculation from session records. Design the data model to support this already — store the raw records in full detail.

---

## 8. Calendar Event Integration

Sessions on `HOLIDAY` or `NO_CLASS_DAY` events:
- Are never created (`session.is_skipped = true` if they were pre-generated before the event was added).
- Have no `AttendanceRecord` rows.
- Do not appear in the weekly attendance view.

If a calendar event is added retroactively:
- Sessions already generated for that date are flagged `is_skipped = true`.
- Existing `AttendanceRecord` rows for those sessions remain but are visually suppressed in the UI.
- Educator is notified to review.
