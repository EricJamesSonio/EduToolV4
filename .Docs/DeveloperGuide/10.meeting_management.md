# DEV-10 — Meeting Management
**EduTool Developer Guide**
> Covers: Meeting room lifecycle, video/audio features, join requests, lesson presentation mode, calendar event suppression.

---

## 1. Overview

EduTool has a built-in video meeting room. No third-party tools. Meetings are attached to classes, opened at a scheduled time, and support real-time lesson presentation synchronized across all participants. Meetings are not recorded.

---

## 2. Data Model

```
Meeting
  id                UUID, primary key
  class_id          FK → Class
  created_by        FK → Educator
  title             string
  description       string, nullable
  scheduled_at      timestamp  -- when the room opens automatically
  ended_at          timestamp, nullable  -- set when educator ends meeting
  status            enum (SCHEDULED | LIVE | ENDED)
  invite_type       enum (ALL | SELECTED)
  created_at        timestamp
  deleted_at        timestamp, nullable (soft delete)

MeetingInvite
  id              UUID, primary key
  meeting_id      FK → Meeting
  student_id      FK → Student

MeetingJoinRequest
  id              UUID, primary key
  meeting_id      FK → Meeting
  student_id      FK → Student
  status          enum (PENDING | ACCEPTED | DECLINED)
  requested_at    timestamp
  resolved_at     timestamp, nullable
```

---

## 3. Meeting Creation

```
POST /classes/{class_id}/meetings

Fields:
  title           required
  description     optional
  scheduled_at    required
  invite_type     ALL | SELECTED
  student_ids     required if invite_type = SELECTED (array of student IDs)

On save:
  1. Create Meeting record, status = SCHEDULED.
  2. If invite_type = ALL:
       Create MeetingInvite for all currently enrolled Active students.
  3. If invite_type = SELECTED:
       Create MeetingInvite for each student_id in the list.
  4. Notify all invited students:
       type = MEETING_CREATED
       message = "A meeting has been scheduled: [title] on [scheduled_at]."
  5. Check Academic Calendar:
       IF scheduled_at falls on HOLIDAY or NO_CLASS_DAY:
         Warn educator: "This date is marked as [event type] on the academic
           calendar. Meeting reminders will be suppressed."
         Do NOT block creation — educator proceeds knowingly.
  6. Log in Educator Activity Log:
       event_type = MEETING_CREATED (add this if useful — not in spec but logical)
```

## 4. Room Lifecycle

### 4.1 Auto-Open at Scheduled Time

```
SCHEDULED JOB (every minute):
  meetings = getMeetings WHERE
    status = SCHEDULED
    AND scheduled_at <= now()

  FOR each meeting:
    UPDATE Meeting SET status = LIVE
    -- Room is now open. Participants can connect.
    -- No notification sent at open time (they were already notified at creation).
```

### 4.2 Joining the Room

Any participant (educator or invited student) can join when `meeting.status = LIVE`.

**Invited students:**
```
FUNCTION joinMeeting(meeting_id, student_id):
  invite = getMeetingInvite(meeting_id, student_id)
  IF invite IS NOT NULL:
    RETURN { allowed: true }  -- join directly
```

**Non-invited students:**
```
  IF invite IS NULL:
    -- Student can see the meeting exists but cannot join directly
    -- They can send a join request
    CREATE MeetingJoinRequest {
      meeting_id, student_id, status: PENDING
    }
    NOTIFY educator (real-time via WebSocket):
      "[Student Name] is requesting to join."
    RETURN { allowed: false, request_sent: true }
```

### 4.3 Educator Handles Join Requests

Inside the live room, educator sees a list of pending join requests.

```
FUNCTION resolveJoinRequest(request_id, decision):
  -- decision: ACCEPTED | DECLINED
  UPDATE MeetingJoinRequest SET status = decision, resolved_at = now()
  IF decision = ACCEPTED:
    NOTIFY student (real-time): "Your join request was accepted."
    -- Student is now allowed into the room
  ELSE:
    NOTIFY student (real-time): "Your join request was declined."
```

### 4.4 Ending the Meeting

Only the educator can end the meeting.

```
FUNCTION endMeeting(meeting_id, educator_id):
  UPDATE Meeting SET status = ENDED, ended_at = now()
  -- Disconnect all active participants from the WebSocket room.
  -- No recording. Nothing is stored about what was discussed.
  LOG educator activity: event_type = MEETING_ENDED
```

There is no auto-end. No duration limit. Meeting stays live until educator ends it.

## 5. Room Features (Real-Time, WebSocket)

All in-room features operate over a WebSocket (or WebRTC signaling) connection. Below is the feature set and signaling events needed.

### 5.1 Video & Audio

Standard WebRTC peer connections. Educator and students all publish/subscribe streams.

Educator controls:
- Mute individual participants: `{ event: "MUTE_PARTICIPANT", target: student_id }`
- Mute all: `{ event: "MUTE_ALL" }`

### 5.2 Chat

Text messages sent to the room during the meeting.

```
MeetingChatMessage
  id              UUID, primary key
  meeting_id      FK → Meeting
  sender_id       FK → User
  sender_name     string  -- snapshot at send time
  message         text
  sent_at         timestamp
```

Persist messages during the meeting for in-room scrollback. Do not expose after meeting ends.

### 5.3 Raise Hand & Reactions

```
-- In-memory only. No persistence needed.
Events:
  { event: "RAISE_HAND", student_id }
  { event: "LOWER_HAND", student_id }
  { event: "REACTION", student_id, type: "THUMBS_UP" | "CLAP" | ... }
```

Broadcast to all room participants via WebSocket.

### 5.4 Screen Sharing

Standard WebRTC screen capture stream. Any participant can share (educator controls who is presenting by managing the room).

### 5.5 Lesson Presentation Mode

See DEV-06 Section 5 for the full specification. Summary:

- Educator selects a lesson and starts "Present".
- All participants receive the lesson content (title + detail).
- Educator navigates forward/backward through sections.
- All participants' views sync in real time.

```
WebSocket events:
  Educator → Room: { event: "PRESENT_LESSON", lesson_id }
  Educator → Room: { event: "LESSON_NAVIGATE", direction: "NEXT" | "PREV" }
  Room → All participants: { event: "LESSON_UPDATE", section_index, content }
  Educator → Room: { event: "END_PRESENTATION" }
```

## 6. Academic Calendar Suppression

Meeting notifications (reminders) are suppressed if the meeting's `scheduled_at` falls on a `HOLIDAY` or `NO_CLASS_DAY` calendar event.

```
SCHEDULED JOB (before meeting reminders would fire):
  CHECK: is meeting.scheduled_at on a suppressed calendar event?
  IF YES: skip sending reminder notifications.
  IF NO: send reminder to invited students.
```

Meeting reminders fire N minutes before `scheduled_at` (choose a reasonable default, e.g. 15 minutes). This is a separate notification from the creation notification.

## 7. Build Order for This Module

```
1. Meeting model + MeetingInvite + MeetingJoinRequest models
2. Meeting creation endpoint
3. Auto-open scheduled job (status SCHEDULED → LIVE)
4. Room join endpoint (invited check + join request creation)
5. Join request resolution endpoint
6. End meeting endpoint
7. MeetingChatMessage model + WebSocket message handler
8. WebRTC signaling server setup (or integrate with existing media server)
9. Educator controls: mute individual, mute all
10. Raise hand / reaction WebSocket events (in-memory, no persistence)
11. Lesson presentation WebSocket events (integrate with DEV-06)
12. Meeting reminder notification job (with calendar suppression check)
13. Soft delete for meeting records
14. Educator UI: meeting creation form, upcoming meetings list, live room UI
    (video grid, chat panel, raise hand panel, join request queue,
     lesson presentation panel, end meeting button)
15. Student UI: meeting list, join meeting, in-room view (video, chat,
    raise hand, lesson view — no navigation controls)
```
