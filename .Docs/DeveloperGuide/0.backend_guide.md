# DEV-00 — Backend Developer Guide
**EduTool — NestJS Backend Architecture & Standards**
> This guide covers how to build and structure the EduTool backend. Read this before touching any DEV-01 through DEV-11 guide. Every decision here applies globally across the entire codebase.

---

## 1. Purpose of This Guide

EduTool is a thesis project with real production intent — other schools may adopt it. That means the backend must be built to a standard that is:

- **Correct** — enforces all business rules from the system spec without shortcuts
- **Secure** — multi-tenant isolation, role-based access, no data leakage between orgs
- **Maintainable** — consistent patterns so any developer can pick up any module
- **Observable** — errors and events are logged; problems are diagnosable
- **Scalable** — designed to handle large student populations (1,000+ per org) without rewriting

This guide establishes the rules. Follow them in every module.

### 4.1 Prisma Service

```typescript
    this.$on('beforeExit', async () => {
      await app.close();
    });
  }
}
```

### 4.2 Soft Delete Middleware

Add a Prisma middleware that automatically filters soft-deleted records from all queries. This enforces the soft delete policy globally without relying on developers to remember `WHERE deleted_at IS NULL` in every query.

```typescript
// database/prisma.service.ts — add to onModuleInit
this.$use(async (params, next) => {
  const modelsWithSoftDelete = [
    'Class', 'Assessment', 'Lesson',
    'Enrollment', 'Meeting', 'Section',
  ];

  if (modelsWithSoftDelete.includes(params.model)) {
    if (params.action === 'findUnique' || params.action === 'findFirst') {
      params.args.where = {
        ...params.args.where,
        deleted_at: null,
      };
      params.action = 'findFirst';
    }

    if (params.action === 'findMany') {
      if (!params.args) params.args = {};
      if (!params.args.where) params.args.where = {};
      params.args.where.deleted_at = null;
    }
  }

  return next(params);
});
```

This means `prisma.class.findMany()` automatically excludes soft-deleted records everywhere. You never need to manually add `deleted_at: null` in individual queries.

> **Exception:** If you explicitly need to query deleted records (platform owner access, audit view), use raw queries or bypass the middleware with a special flag.

### 4.3 Schema Conventions

```prisma
// Every model follows these conventions:
model Example {
  id          String    @id @default(uuid())
  org_id      String
  created_at  DateTime  @default(now())
  updated_at  DateTime  @updatedAt
  deleted_at  DateTime? // nullable = soft deletable

  org         Organization @relation(fields: [org_id], references: [id])

  @@index([org_id])           // always index org_id
  @@index([deleted_at])       // always index deleted_at if present
  @@map("examples")           // snake_case table names
}
```

Rules:
- All primary keys are UUIDs (`@default(uuid())`).
- All timestamps in UTC.
- All table names snake_case via `@@map`.
- Every table that belongs to an org has `org_id` indexed.
- Every soft-deletable table has `deleted_at` indexed.

## 5. Authentication

### 5.1 JWT Strategy

EduTool uses two tokens: an access token (short-lived) and a refresh token (long-lived).

```typescript
// JWT payload shape
interface JwtPayload {
  sub: string;         // user.id
  role: UserRole;      // ADMIN | EDUCATOR | STUDENT
  org_id: string;      // organization.id
  iat: number;
  exp: number;
}
```

**Access token:** 15 minutes (short — limits exposure if leaked).
**Refresh token:** 30 days. Stored in Redis. Used to issue new access tokens.

### 5.2 Token Invalidation (Critical for Password Reset)

The spec requires that old passwords stop working immediately when Admin resets them. With stateless JWTs this is impossible without a blocklist.

Implementation:
```typescript
// On password reset:
// 1. Generate new password + hash
// 2. Save to DB
// 3. Delete ALL refresh tokens for this user from Redis:
await redis.del(`refresh_token:${userId}`)
// 4. Add current access token to blocklist with TTL = token's remaining lifetime:
await redis.set(`blocklist:${accessToken}`, '1', 'EX', remainingSeconds)
```

```typescript
// In JwtAuthGuard — check blocklist on every request:
const isBlocked = await redis.get(`blocklist:${token}`)
if (isBlocked) throw new UnauthorizedException('Token has been revoked.')
```

This means the moment Admin resets a password, every active session for that user is immediately invalid.

### 5.3 Auth Flow

```
POST /auth/login
  Body: { email, password }
  → Validate credentials
  → Generate access_token + refresh_token
  → Store refresh_token in Redis: SET refresh_token:{userId} {token} EX 30d
  → Return both tokens

POST /auth/refresh
  Body: { refresh_token }
  → Validate token signature
  → Check it exists in Redis (not revoked)
  → Issue new access_token
  → Rotate refresh_token (delete old, store new)

POST /auth/logout
  → Delete refresh_token from Redis
  → Add access_token to blocklist
```

### 5.4 Passwords

```typescript
// utils/password.util.ts
import { randomBytes } from 'crypto'
import * as bcrypt from 'bcrypt'

export function generatePassword(length = 10): string {
  const chars = 'ABCDEFGHJKLMNPQRSTUVWXYZabcdefghjkmnpqrstuvwxyz23456789'
  // Note: removed ambiguous chars (0, O, I, l, 1) for readability on paper
  return Array.from(
    { length },
    () => chars[randomBytes(1)[0] % chars.length]
  ).join('')
}

export async function hashPassword(plain: string): Promise<string> {
  return bcrypt.hash(plain, 12) // 12 rounds is secure and not too slow
}

export async function verifyPassword(plain: string, hash: string): Promise<boolean> {
  return bcrypt.compare(plain, hash)
}
```

### 6.4 Org Isolation Guard (Critical)

This is the most important security rule in the entire system. Every resource belongs to an org. A user must never be able to access resources from a different org, even if they guess a valid ID.

```typescript
// common/guards/org.guard.ts
@Injectable()
export class OrgGuard implements CanActivate {
  constructor(private prisma: PrismaService) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const request = context.switchToHttp().getRequest()
    const user: JwtPayload = request.user
    const resourceOrgId = await this.resolveResourceOrgId(request)

    if (!resourceOrgId) return true // resource has no org (e.g. public routes)
    if (resourceOrgId !== user.org_id) {
      throw new ForbiddenException('Access denied.')
    }
    return true
  }

  private async resolveResourceOrgId(request: Request): Promise<string | null> {
    // Resolve org_id from the resource being accessed
    // Implementation varies per route — use a decorator to hint the entity type
    // e.g. @OrgResource('Class') → look up class.org_id from params.id
    // ...
  }
}
```

**Rule:** Every service method that fetches a resource by ID must also filter by `org_id`. Never fetch by ID alone.

```typescript
// WRONG — vulnerable to cross-org access
const student = await this.prisma.student.findUnique({ where: { id } })

// CORRECT — always include org_id in the query
const student = await this.prisma.student.findFirst({
  where: { id, org_id: user.org_id }
})
if (!student) throw new NotFoundException('Student not found.')
```

If the record doesn't exist OR belongs to a different org, throw `NotFoundException` — not `ForbiddenException`. This prevents leaking whether the ID exists in another org.

## 7. Validation

### 7.1 Global Validation Pipe

```typescript
// main.ts
app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true,           // strip unknown fields — never trust client input
    forbidNonWhitelisted: true, // throw error if unknown fields sent
    transform: true,           // auto-transform types (string '3' → number 3)
    transformOptions: {
      enableImplicitConversion: true,
    },
  })
)
```

`whitelist: true` is critical. It prevents clients from injecting unexpected fields into DTOs.

### 7.2 DTO Patterns

```typescript
// dto/create-student.dto.ts
import { IsString, IsEmail, IsEnum, IsOptional, IsUUID, MinLength } from 'class-validator'
import { Transform } from 'class-transformer'

export class CreateStudentDto {
  @IsString()
  @MinLength(2)
  @Transform(({ value }) => value?.trim())
  full_name: string

  @IsEmail()
  @Transform(({ value }) => value?.toLowerCase().trim())
  email: string

  @IsString()
  student_id: string

  @IsEnum(LevelSection)
  level_section: LevelSection

  @IsString()
  grade_year: string

  @IsUUID()
  @IsOptional()
  section_id?: string

  @IsUUID()
  @IsOptional()
  strand_id?: string

  @IsUUID()
  @IsOptional()
  course_id?: string
}
```

Rules for DTOs:
- Always `@Transform` string inputs to `.trim()` — prevents whitespace-only values.
- Always `@Transform` emails to `.toLowerCase()` — prevents duplicate accounts.
- Mark all optional fields explicitly with `@IsOptional()`.
- Use `@IsUUID()` for all ID fields — rejects malformed IDs early before hitting the DB.

### 7.3 Custom Validators

For business-rule validations that need DB access (e.g. checking if a `section_id` belongs to the org), do NOT put them in DTOs. Put them in the service layer and throw appropriate exceptions there.

## 8. Error Handling

### 8.1 Global Exception Filter

```typescript
// common/filters/http-exception.filter.ts
@Catch()
export class GlobalExceptionFilter implements ExceptionFilter {
  private readonly logger = new Logger(GlobalExceptionFilter.name)

  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp()
    const response = ctx.getResponse<Response>()
    const request = ctx.getRequest<Request>()

    let status = HttpStatus.INTERNAL_SERVER_ERROR
    let message = 'Internal server error'
    let code = 'INTERNAL_ERROR'

    if (exception instanceof HttpException) {
      status = exception.getStatus()
      const res = exception.getResponse()
      message = typeof res === 'string' ? res : (res as any).message
      code = (res as any).code || this.statusToCode(status)
    } else if (exception instanceof Prisma.PrismaClientKnownRequestError) {
      // Handle Prisma errors
      if (exception.code === 'P2002') {
        status = HttpStatus.CONFLICT
        message = 'A record with this value already exists.'
        code = 'DUPLICATE_ENTRY'
      } else if (exception.code === 'P2025') {
        status = HttpStatus.NOT_FOUND
        message = 'Record not found.'
        code = 'NOT_FOUND'
      }
    }

    // Log server errors (5xx) with full stack — not 4xx (those are client mistakes)
    if (status >= 500) {
      this.logger.error(
        `${request.method} ${request.url} → ${status}`,
        exception instanceof Error ? exception.stack : String(exception)
      )
    }

    response.status(status).json({
      success: false,
      statusCode: status,
      code,
      message,
      timestamp: new Date().toISOString(),
      path: request.url,
    })
  }
}
```

Register globally in `main.ts`:
```typescript
app.useGlobalFilters(new GlobalExceptionFilter())
```

### 8.2 Standard Error Response Shape

Every error response from the API has this shape — no exceptions:

```json
{
  "success": false,
  "statusCode": 404,
  "code": "NOT_FOUND",
  "message": "Student not found.",
  "timestamp": "2025-01-15T10:30:00.000Z",
  "path": "/students/abc-123"
}
```

The `code` field is machine-readable. The frontend uses it to show correct UI messages. Never rely on the `message` string for frontend logic.

### 8.3 Standard Success Response Shape

```typescript
// common/interceptors/response.interceptor.ts
@Injectable()
export class ResponseInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    return next.handle().pipe(
      map(data => ({
        success: true,
        data,

}
```

Every success response:
```json
{
  "success": true,
  "data": { ... },
  "timestamp": "2025-01-15T10:30:00.000Z"
}
```

### 8.4 Exception Vocabulary — Use Consistently

| Situation | Exception to throw |
|---|---|
| Resource not found (or wrong org) | `NotFoundException` |
| Authenticated but not allowed | `ForbiddenException` |
| Not authenticated | `UnauthorizedException` |
| Input validation failed | `BadRequestException` |
| Duplicate record | `ConflictException` |
| Business rule violated | `UnprocessableEntityException` |
| Unexpected server error | Let it bubble — GlobalExceptionFilter catches it |

Never throw generic `Error`. Always use NestJS HTTP exceptions so the filter can map them correctly.

## 9. Middleware

### 9.1 Request Logger Middleware

```typescript
// common/middleware/logger.middleware.ts
@Injectable()
export class LoggerMiddleware implements NestMiddleware {
  private logger = new Logger('HTTP')

  use(req: Request, res: Response, next: NextFunction) {
    const { method, originalUrl } = req
    const start = Date.now()

    res.on('finish', () => {
      const { statusCode } = res
      const duration = Date.now() - start
      const level = statusCode >= 500 ? 'error' : statusCode >= 400 ? 'warn' : 'log'
      this.logger[level](
        `${method} ${originalUrl} ${statusCode} — ${duration}ms`
      )
    })

    next()
  }
}
```

Apply globally in `AppModule`:
```typescript
configure(consumer: MiddlewareConsumer) {
  consumer.apply(LoggerMiddleware).forRoutes('*')
}
```

### 10.2 Processor Pattern

```typescript
// concept-extraction/concept-extraction.processor.ts
@Processor('concept-extraction')
export class ConceptExtractionProcessor extends WorkerHost {
  private logger = new Logger(ConceptExtractionProcessor.name)

  async process(job: Job<{ buildId: string; lessonDetail: string }>) {
    const { buildId, lessonDetail } = job.data

    try {
      // Update status to RUNNING
      await this.prisma.conceptBuild.update({
        where: { id: buildId },
        data: { status: 'RUNNING' },
      })

      // Call AI service
      const result = await this.aiService.extractConcepts(lessonDetail)

      // Update with results
      await this.prisma.conceptBuild.update({
        where: { id: buildId },
        data: {
          sections: result,
          total_items: result.reduce((sum, s) => sum + s.available_items, 0),
          status: 'COMPLETE',
          completed_at: new Date(),
        },
      })

      // Update lesson
      await this.prisma.lesson.update({
        where: { id: lesson.id },
        data: { has_concept_build: true, concept_build_id: buildId },
      })

      // Notify educator
      await this.notificationsService.notify(...)
      await this.activityLogService.log(...)

    } catch (error) {
      this.logger.error(`Concept extraction failed for build ${buildId}`, error)

      await this.prisma.conceptBuild.update({
        where: { id: buildId },
        data: { status: 'FAILED' },
      })

      // Notify educator of failure
      await this.notificationsService.notify(...)

      throw error // Re-throw so BullMQ marks job as failed and can retry
    }
  }
}
```

```typescript
  { repeat: { every: 60000 } }  // every 1 minute
)

await this.notificationQueue.add(
  'archive-old-notifications',
  {},
  { repeat: { cron: '0 2 * * *' } }  // daily at 2am
)
```

Scheduled jobs covered:
- Close expired assessment attempts (every 1 min)
- Release scheduled assessments (every 1 min)
- Send deadline approaching notifications (every 15 min)
- Auto-lock grades at window deadline (every 1 min)
- Open meeting rooms at scheduled time (every 1 min)
- Archive notifications older than 90 days (daily)
- Send meeting reminders (every 5 min)

## 11. Pagination

All list endpoints must paginate. Never return unbounded lists — orgs can have 1,000+ students.

### 11.1 Standard Pagination DTO

```typescript
// common/dto/pagination.dto.ts
export class PaginationDto {
  @IsOptional()
  @Type(() => Number)
  @IsInt()
  @Min(1)
  page?: number = 1

  @IsOptional()
  @Type(() => Number)
  @IsInt()
  @Min(1)
  @Max(100)
  limit?: number = 20
}

// common/dto/paginated-response.dto.ts
export class PaginatedResponse<T> {
  data: T[]
  meta: {
    total: number
    page: number
    limit: number
    total_pages: number
    has_next: boolean
    has_prev: boolean
  }
}
```

### 11.2 Prisma Pagination Helper

```typescript
// common/utils/paginate.util.ts
export async function paginate<T>(
  model: any,
  args: Prisma.Args<any, 'findMany'>,
  page: number,
  limit: number,
): Promise<PaginatedResponse<T>> {
  const skip = (page - 1) * limit
  const [data, total] = await Promise.all([
    model.findMany({ ...args, skip, take: limit }),
    model.count({ where: args.where }),
  ])
  return {
    data,
    meta: {
      total,
      page,
      limit,
      total_pages: Math.ceil(total / limit),
      has_next: page * limit < total,
      has_prev: page > 1,
    },
  }
}
```

## 12. Multi-Tenancy Rules

These rules are non-negotiable. Every violation is a potential data breach.

**Rule 1:** Every service method that accesses org-scoped data takes `org_id` as a parameter. It never reads `org_id` from anywhere else.

**Rule 2:** Every Prisma query on an org-scoped model includes `org_id` in the `where` clause.

**Rule 3:** The `org_id` used in queries always comes from `request.user.org_id` (the JWT payload) — never from the request body or URL params. A client cannot claim to belong to a different org.

**Rule 4:** Cross-org joins are never performed. If two records from different orgs happen to share an ID (impossible with UUIDs but worth stating), they must never be linked.

**Rule 5:** All `NotFoundException` responses look identical whether the record doesn't exist or belongs to a different org. Never reveal which org a resource belongs to.

## 13. Transactions

Any operation that writes to multiple tables must use a Prisma transaction. If one write fails, all writes roll back.

```typescript
// Example: enrolling a student (creates Enrollment + creates AttendanceRecords)
await this.prisma.$transaction(async (tx) => {
  const enrollment = await tx.enrollment.create({
    data: { student_id, class_id, enrolled_at: new Date(), added_by: 'AUTO' },
  })

  const sessions = await tx.classSession.findMany({
    where: { class_id, date: { gte: new Date() }, is_skipped: false },
  })

  await tx.attendanceRecord.createMany({
    data: sessions.map(session => ({
      class_id,
      session_id: session.id,
      student_id,
      status: null,
      source: 'MANUAL',
    })),
  })

  return enrollment
})
```

Critical flows that always need transactions:
- Student enrollment (enrollment + attendance records)
- Grade locking (grade updates + score publishing + notifications)
- Password reset (password update + token invalidation)
- Status change to Dropped/Transferred (status update + enrollment removals)
- Assessment deletion (soft delete + score wipe + grade recompute trigger)

## 14. Logging

### 14.1 NestJS Logger

Use NestJS's built-in Logger. Never use `console.log` in production code.

```typescript
// In any service:
private readonly logger = new Logger(StudentsService.name)

this.logger.log('Student created successfully')           // INFO
this.logger.warn('Section capacity reached')              // WARN
this.logger.error('Failed to generate assessment', stack) // ERROR
this.logger.debug('Enrollment validation started')        // DEBUG (dev only)
```

### 14.2 What to Log

| Level | When |
|---|---|
| `log` | Successful significant operations (account created, grade locked, import completed) |
| `warn` | Recoverable issues (capacity hit, auto-lock fired, job retried) |
| `error` | Unrecoverable failures (job failed after retries, DB connection lost) |
| `debug` | Detailed flow tracing — only in development |

Do NOT log sensitive data: passwords (even hashed), JWT tokens, personal student information in log messages.

### 14.3 Structured Logging (Production)

For production, swap NestJS's default logger for a structured logger like `pino` via `nestjs-pino`. Structured (JSON) logs are easier to search in log aggregation tools (Datadog, Loki, CloudWatch).

```typescript
// main.ts (production)
import { Logger } from 'nestjs-pino'
app.useLogger(app.get(Logger))
```

## 16. Health Check Endpoint

Always expose a health check. Required for Docker, load balancers, and uptime monitoring.

```typescript
// health/health.controller.ts
@Controller('health')
@SkipThrottle()
export class HealthController {
  constructor(
    private health: HealthCheckService,
    private db: PrismaHealthIndicator,
    private redis: RedisHealthIndicator,
  ) {}

  @Get()
  @HealthCheck()
  check() {
    return this.health.check([
      () => this.db.pingCheck('database'),
      () => this.redis.checkHealth('redis'),
    ])
  }
}
```

`GET /health` returns `{ status: 'ok' }` when everything is healthy. Returns 503 when any dependency is down.

## 17. Security Checklist

Before shipping any endpoint, verify:

- [ ] Route is protected by `JwtAuthGuard`
- [ ] Route has correct `@Roles()` decorator
- [ ] Service method filters by `org_id` from JWT, not from request params
- [ ] No unbounded queries (pagination or explicit `take` limit)
- [ ] No raw SQL with user input (use Prisma parameterized queries only)
- [ ] Sensitive fields excluded from response DTOs (no `password_hash`, no `generated_password`)
- [ ] Errors throw correct NestJS exceptions (no raw `throw new Error()`)
- [ ] Multi-table operations wrapped in `$transaction`
- [ ] Input DTOs use `whitelist: true` (enforced globally but verify per DTO)
