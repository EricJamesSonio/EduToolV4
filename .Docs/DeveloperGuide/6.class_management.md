# DEV-06 — Lesson Management
**EduTool Developer Guide**
> Covers: Lesson CRUD, concept extraction, presentation mode.

---

## 1. Overview

Lessons are the content units that educators create per class. They are organized by week and feed directly into the AI assessment generator via a background concept extraction job. This guide covers the full lifecycle: creation, editing, concept extraction, and the in-meeting presentation mode.

---

## 2. Lesson Data Model

```
Lesson
  id                UUID, primary key
  class_id          FK → Class
  title             string, required
  description       string, nullable
  week_session_id   FK → ClassSession  -- which week/session this belongs to
  detail            text  -- min 10 words required before saving
  detail_word_count integer  -- computed on save
  has_concept_build boolean, default false
  concept_build_id  FK → ConceptBuild, nullable
  created_at        timestamp
  updated_at        timestamp
  deleted_at        timestamp, nullable (soft delete)
```

### 2.1 Validation Rules

- `title`: required, non-empty.
- `detail`: minimum 10 words. Count words on the backend (split on whitespace, trim). If under 10 words, reject save with: "Lesson detail must be at least 10 words."
- `week_session_id`: must belong to the same `class_id`.

## 3. Concept Extraction

### 3.1 Purpose

Concept extraction reads the lesson's `detail` text, identifies distinct academic concepts and how many questions can be generated from each, and stores that as a `ConceptBuild`. The Assessment Generator (DEV-07) uses this build to configure assessment ranges.

### 3.2 ConceptBuild Data Model

```
ConceptBuild
  id              UUID, primary key
  lesson_id       FK → Lesson
  class_id        FK → Class
  sections        JSON array:
                    [
                      { "concept": "Stack", "available_items": 5 },
                      { "concept": "Queue", "available_items": 6 },
                      ...
                    ]
  total_items     integer  -- sum of all available_items
  status          enum (PENDING | RUNNING | COMPLETE | FAILED)
  triggered_by    enum (AUTO | MANUAL)
  created_at      timestamp
  completed_at    timestamp, nullable
```

### 3.3 Trigger Rules

| Trigger | Condition |
|---|---|
| **Auto** | Lesson `detail` is saved for the first time with 10+ words and `has_concept_build = false` |
| **Manual** | Educator explicitly clicks "Re-extract Concepts" on a lesson that already has a concept build |

Rules:
- Auto trigger fires exactly once — on first save of a qualifying detail. Not on subsequent edits.
- If detail is updated after a build exists: the **existing build is kept unchanged.** Auto-trigger does NOT fire again. Educator must manually trigger re-extraction when ready.
- Manual re-extraction replaces the previous concept build entirely.
- Re-extraction does **not** affect assessments already generated from the old build. Only new assessments use the updated build.

### 3.4 Extraction Flow

```
FUNCTION triggerConceptExtraction(lesson_id, trigger_type):

  lesson = getLesson(lesson_id)

  -- Create a new ConceptBuild in PENDING state
  build = CREATE ConceptBuild {
    lesson_id,
    class_id: lesson.class_id,
    status: PENDING,
    triggered_by: trigger_type
  }

  -- If replacing a previous build (manual re-extraction):
  IF lesson.concept_build_id IS NOT NULL:
    previous_build = getConceptBuild(lesson.concept_build_id)
    -- Keep previous_build in DB for historical reference (do not delete)
    -- New build will replace the reference on completion

  -- Queue background job
  ENQUEUE job: extractConcepts(build.id, lesson.detail)

  -- Update build status
  UPDATE ConceptBuild SET status = RUNNING WHERE id = build.id

  -- Background job runs:
  FUNCTION extractConcepts(build_id, lesson_detail):
    TRY:
      -- Call AI service to extract concepts and item counts
      result = AI.extractConcepts(lesson_detail)
      -- result: [{ concept: string, available_items: int }, ...]

      UPDATE ConceptBuild SET
        sections = result,
        total_items = sum(result.available_items),
        status = COMPLETE,
        completed_at = now()
      WHERE id = build_id

      -- Link lesson to new build
      UPDATE Lesson SET
        concept_build_id = build_id,
        has_concept_build = true
      WHERE id = lesson_id

      -- Send in-app notification to educator
      NOTIFY educator of lesson.class_id:
        type = CONCEPT_EXTRACTION_COMPLETE
        message = "Concept extraction complete for lesson: [lesson.title]"

      -- Log in Educator Activity Log
      LOG: event_type = CONCEPT_EXTRACTION_COMPLETED, class_id, details = { lesson_id, build_id }

    CATCH error:
      UPDATE ConceptBuild SET status = FAILED WHERE id = build_id
      NOTIFY educator: "Concept extraction failed for lesson [title]. Try re-extracting."
```

### 3.5 Status Display to Educator

| ConceptBuild status | What educator sees |
|---|---|
| None (no build) | "No concept build. Save lesson detail (min 10 words) to generate." |
| `PENDING` / `RUNNING` | "Extracting concepts... You will be notified when complete." |
| `COMPLETE` | List of concept sections with available item counts |
| `FAILED` | "Extraction failed. Click Re-extract to try again." |

## 4. Lesson UI — Weekly Calendar View

### 4.1 Layout

Educator sees lessons organized by week session label (matching the class's `ClassSession` week labels — see DEV-05 Section 5.2).

```
Week 1        → lessons tagged to week 1 sessions
Week 2        → lessons tagged to week 2 sessions
...
```

For multi-day classes, lessons can be tagged to a specific sub-session (e.g. Week 1.2).

### 4.2 Educator Actions per Lesson

- Create new lesson (title, description, detail, week assignment)
- Edit lesson (title, description, detail)
- View concept build status and sections
- Trigger manual re-extraction
- Delete lesson (soft delete — see rules below)

### 4.3 Lesson Deletion Rules

```
IF lesson has an assessment generated from its concept build:
  Warn: "Deleting this lesson will not delete its assessments.
         Assessments from this lesson will remain. Confirm?"
IF lesson has no assessments:
  No warning needed.
Soft-delete: lesson.deleted_at = now()
Log in Educator Activity Log: event_type = LESSON_DELETED (if you add this event)
```

## 5. Presentation Mode

### 5.1 Purpose

During a video meeting, the educator can push lesson content to all participants so they see it in real time (forward/backward navigation is synchronized).

### 5.2 Behavior

- Educator opens a meeting room and starts "Present Lesson".
- Educator selects which lesson to present.
- All invited participants in the room see the lesson detail content.
- Educator navigates forward/backward through sections of the lesson.
- All participants' views update in real time (push via WebSocket or similar).
- Only the educator controls navigation. Participants are viewers only.

### 5.3 Implementation Notes

- This is a real-time sync feature, not a recording. Nothing is stored about what was presented.
- When the meeting ends, presentation mode ends with it.
- If the educator closes presentation mode without ending the meeting, participants return to the standard meeting view.
- Integrate with the meeting room's WebSocket channel (see DEV-10).
