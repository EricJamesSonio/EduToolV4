# DEV-07 — Assessment Management
**EduTool Developer Guide**
> Covers: Assessment configuration, AI generation, question editing, student assignment, attempt control, score publishing, deletion.

---

## 1. Overview

Assessments are AI-generated from lesson concept builds. The educator configures a template (which lesson, how many items, what types), the system generates questions in the background, and the educator reviews and assigns them to students. Students take assessments with a single-attempt-per-session guarantee.

---

## 2. Data Models

### 2.1 Assessment

```
Assessment
  id                UUID, primary key
  class_id          FK → Class
  lesson_id         FK → Lesson
  concept_build_id  FK → ConceptBuild  -- snapshot of build used at gen time
  title             string
  type              enum (QUIZ | ACTIVITY | EXAM | CUSTOM)
  total_items       integer
  release_date      timestamp  -- questions hidden before this
  end_date          timestamp  -- submissions close at this time
  status            enum (DRAFT | GENERATING | READY | RELEASED | CLOSED)
  created_by        FK → Educator
  created_at        timestamp
  deleted_at        timestamp, nullable (soft delete)
```

### 2.2 AssessmentRange

```
AssessmentRange
  id              UUID, primary key
  assessment_id   FK → Assessment
  item_start      integer  -- e.g. 1
  item_end        integer  -- e.g. 10
  question_type   enum (MULTIPLE_CHOICE | TRUE_OR_FALSE | IDENTIFICATION |
                        ENUMERATION | ESSAY)
  concept_sections  JSON array of strings
                    -- e.g. ["Stack", "Queue", "Arrays"]
                    -- must sum to (item_end - item_start + 1)
```

### 2.3 Question

```
Question
  id              UUID, primary key
  assessment_id   FK → Assessment
  range_id        FK → AssessmentRange
  item_number     integer  -- position in assessment (1-based)
  question_type   enum
  question_text   text
  choices         JSON, nullable
                  -- MC: [{ "label": "A", "text": "...", "is_correct": bool }]
                  -- T/F: [{ "text": "True", "is_correct": bool }, ...]
  correct_answer  text, nullable
                  -- Identification/Enumeration: expected answer(s)
                  -- Essay: null (no correct answer stored)
  is_locked       boolean, default false  -- true after release_date passes
  created_at      timestamp
  updated_at      timestamp
```

### 2.4 StudentAssessment

```
StudentAssessment
  id              UUID, primary key
  assessment_id   FK → Assessment
  student_id      FK → Student
  status          enum (NULL | EXEMPTED | CUSTOM | SUBMITTED | DRAFT)
                  -- UI display labels:
                  --   NULL      → "Not Assigned"
                  --   EXEMPTED  → "Exempted"
                  --   CUSTOM    → "Customized"   ← system plan uses this label
                  --   SUBMITTED → "Submitted"
                  --   DRAFT     → "Draft"
  custom_score    decimal, nullable  -- set if status = CUSTOM
  score           decimal, nullable  -- set after auto-grading
  score_published boolean, default false
  assigned_by     FK → Educator
  assigned_at     timestamp
  updated_at      timestamp
```

### 2.5 AssessmentAttempt

```
AssessmentAttempt
  id              UUID, primary key
  student_assessment_id  FK → StudentAssessment
  student_id      FK → Student
  assessment_id   FK → Assessment
  status          enum (ACTIVE | SUBMITTED | CLOSED)
  answers         JSON  -- auto-saved progress
                        -- { item_number: answer_value }
  opened_at       timestamp
  submitted_at    timestamp, nullable
  closed_at       timestamp, nullable  -- set when end_date forces close
```

## 3. Assessment Configuration & Generation Flow

### 3.1 Step 1 — Select Lesson

Educator selects a lesson. System checks:
```
IF lesson.has_concept_build = false OR lesson.concept_build.status != COMPLETE:
  Block. Show: "This lesson has no complete concept build. Save lesson
               detail and wait for extraction to complete."
```

If valid, display the concept build's sections and item counts:
```
Stack: 5 | Queue: 6 | Binary Tree: 4 | Linear Data: 5
Total available: 20 items
```

### 3.2 Step 2 — Set Type and Total Items

Educator sets:
- Assessment type: `QUIZ | ACTIVITY | EXAM | CUSTOM`
- Total items: integer

Validate:
```
IF total_items > concept_build.total_items:
  ERROR: "Total items ([N]) cannot exceed concept build total ([M])."
```

### 3.3 Step 3 — Build Item Ranges

Educator defines ranges. Each range specifies:
- Item span: `item_start` to `item_end`
- Question type (one per range)
- Concept sections to fulfill the count

Validation per range:
```
range_count = item_end - item_start + 1
section_sum = sum of available_items for selected concept sections
IF section_sum < range_count:
  ERROR: "Selected sections provide only [M] items but range needs [N].
          Add more concept sections."
```

All ranges together must cover items 1 through `total_items` with no gaps and no overlaps.

```
ranges sorted by item_start:
  ranges[0].item_start must = 1
  For i > 0: ranges[i].item_start must = ranges[i-1].item_end + 1
  Last range's item_end must = total_items
```

### 3.4 Step 4 — Generate

```
FUNCTION generateAssessment(assessment_id):

  -- Create Assessment record with status = GENERATING
  -- Queue background job

  BACKGROUND JOB:
    assessment = getAssessment(assessment_id)
    FOR each range in assessment.ranges:
      count_needed = range.item_end - range.item_start + 1
      FOR i in 1..count_needed:
        question = AI.generateQuestion(
          type: range.question_type,
          concepts: range.concept_sections,
          lesson_detail: assessment.lesson.detail
        )
        CREATE Question {
          assessment_id,
          range_id: range.id,
          item_number: range.item_start + (i - 1),
          question_type: range.question_type,
          question_text: question.text,
          choices: question.choices,
          correct_answer: question.correct_answer
        }

    UPDATE Assessment SET status = READY
    NOTIFY educator: type = ASSESSMENT_GENERATION_COMPLETE,
                     message = "Assessment '[title]' is ready for review."
    LOG educator activity: event_type = ASSESSMENT_CREATED
```

### 3.5 Step 5 — Review, Edit, Configure Dates, Assign

After generation completes:
1. Educator reviews all questions (see Section 4).
2. Educator sets `release_date` and `end_date`.
3. Educator assigns to students (see Section 5).

## 4. Question Editing

Rules:
- Educator can edit any question **before** `release_date`.
- Editable: `question_text`, `choices` (MC), `correct_answer`.
- Essay `question_text` is editable like any other type.
- Once `release_date` passes: set `question.is_locked = true` on all questions. No further edits allowed.

```
FUNCTION lockQuestions(assessment_id):
  -- Triggered by a scheduled job that checks release dates
  UPDATE Question SET is_locked = true
  WHERE assessment_id = assessment_id

  UPDATE Assessment SET status = RELEASED
  WHERE id = assessment_id

  NOTIFY assigned students: type = ASSESSMENT_RELEASED,
    message = "Assessment '[title]' is now available."
```

## 5. Student Assignment & Status

### 5.1 Assigning Students

After generation, educator assigns the assessment to students. Educator can assign:
- All enrolled students in the class
- A selected subset

On assignment: `StudentAssessment` records are created with `status = NULL`.

### 5.2 Status Meanings

| Status | Meaning |
|---|---|
| `NULL` | Assigned but not opened. Treated as missed in grade computation. Educator can override. |
| `DRAFT` | Opened by student, not yet submitted. Auto-saved progress exists. |
| `SUBMITTED` | Submitted within end_date. Auto-graded (except Essay). |
| `EXEMPTED` | Excused. Excluded from grade computation. Counts as perfect score. |
| `CUSTOM` | Educator manually set a score. Uses `custom_score` value. |

### 5.3 Late Student Additions

When a student is enrolled in a class mid-semester (auto or by Admin), for every past assessment where a `StudentAssessment` record does not exist:
- Educator manually creates a `StudentAssessment` with one of: `NULL`, `EXEMPTED`, or `CUSTOM`.
- System does not auto-assign a status for past assessments.

## 6. Assessment Attempt Control

This is a critical feature. Each student has **exactly one active attempt** per assessment at any time.

### 6.1 Opening an Assessment

```
FUNCTION openAssessment(student_id, assessment_id):

  -- Check assessment is RELEASED and end_date has not passed
  assessment = getAssessment(assessment_id)
  IF assessment.status != RELEASED:
    RETURN error: "Assessment not yet available."
  IF now() > assessment.end_date:
    RETURN error: "This assessment has closed."

  -- Check student is assigned
  sa = getStudentAssessment(student_id, assessment_id)
  IF sa IS NULL OR sa.status = EXEMPTED OR sa.status = CUSTOM:
    RETURN error: "You are not assigned this assessment."
  IF sa.status = SUBMITTED:
    RETURN error: "You have already submitted this assessment."

  -- Check for existing active attempt
  existing_attempt = getAttempt(student_id, assessment_id, status: ACTIVE)
  IF existing_attempt IS NOT NULL:
    -- Resume — do not create a new attempt
    RETURN { attempt_id: existing_attempt.id, answers: existing_attempt.answers }

  -- No existing attempt — create new
  attempt = CREATE AssessmentAttempt {
    student_assessment_id: sa.id,
    student_id,
    assessment_id,
    status: ACTIVE,
    answers: {},
    opened_at: now()
  }
  UPDATE StudentAssessment SET status = DRAFT WHERE id = sa.id

  RETURN { attempt_id: attempt.id, answers: {} }
```

### 6.2 Auto-Save

```
FUNCTION saveProgress(attempt_id, answers):
  -- answers: { item_number: answer_value }
  UPDATE AssessmentAttempt SET answers = answers WHERE id = attempt_id
  -- This is a lightweight write — call on every answer change (debounced on client)
```

### 6.3 Submission

```
FUNCTION submitAssessment(attempt_id):
  attempt = getAttempt(attempt_id)
  IF attempt.status != ACTIVE:
    RETURN error: "Attempt is not active."

  -- Auto-grade all non-Essay questions
  assessment = getAssessment(attempt.assessment_id)
  questions = getQuestions(assessment.id)
  score = 0
  total_gradeable = 0
  FOR each question in questions:
    IF question.question_type = ESSAY:
      CONTINUE  -- not auto-graded
    total_gradeable += 1
    student_answer = attempt.answers[question.item_number]
    IF isCorrect(student_answer, question.correct_answer, question.question_type):
      score += 1

  -- Update records
  UPDATE AssessmentAttempt SET status = SUBMITTED, submitted_at = now()
  UPDATE StudentAssessment SET
    status = SUBMITTED,
    score = score / total_gradeable * 100  -- percentage, or raw if preferred

  -- If all questions are Essay type: score stays null until educator grades
```

### 6.4 Auto-Close on End Date

```
SCHEDULED JOB (runs every minute or via cron):
  expired = getAssessments WHERE end_date <= now() AND status = RELEASED

  FOR each assessment:
    UPDATE Assessment SET status = CLOSED

    -- Close all ACTIVE attempts
    UPDATE AssessmentAttempt SET status = CLOSED, closed_at = now()
    WHERE assessment_id = assessment.id AND status = ACTIVE

    -- Mark DRAFT StudentAssessments as NULL (not submitted)
    UPDATE StudentAssessment SET status = NULL
    WHERE assessment_id = assessment.id AND status = DRAFT
```

## 7. Essay Grading

Essay questions are not auto-graded. Educator grades them manually.

```
EssayGrade
  id                    UUID, primary key
  student_assessment_id FK → StudentAssessment
  question_id           FK → Question
  score                 decimal  -- out of question's max (typically 1 point each)
  graded_by_educator_id FK → Educator
  graded_at             timestamp
```

When all essay questions in a submission are graded:
- Recompute the student's total `StudentAssessment.score` including essay scores.
- Update `StudentAssessment.score`.

## 8. Score Publishing

```
StudentAssessment.score_published = false  -- default

Educator can:
  Publish all:    UPDATE score_published = true WHERE assessment_id = X
  Publish selected: UPDATE score_published = true WHERE id IN [...]
  Unpublish:      UPDATE score_published = false WHERE id IN [...]

On grade lock (see DEV-09):
  UPDATE score_published = true WHERE assessment_id IN [class's assessments]
  -- Forces all scores visible when grades lock
```

Students only see their score when `score_published = true` AND the student is the record owner.

## 9. Assessment Deletion

```
FUNCTION deleteAssessment(assessment_id, educator_id):

  assessment = getAssessment(assessment_id)
  has_submissions = exists StudentAssessment WHERE
    assessment_id = assessment_id AND status = SUBMITTED

  IF has_submissions:
    WARN educator: "Students have submitted this assessment. Deleting will
      wipe all their scores. Final grades will recompute without this
      assessment. This cannot be undone. Confirm?"

  -- Soft delete
  UPDATE Assessment SET deleted_at = now() WHERE id = assessment_id

  -- Scores are wiped: delete StudentAssessment records (hard delete is
  --   acceptable here per spec since scores are irreversibly gone)
  DELETE FROM StudentAssessment WHERE assessment_id = assessment_id

  -- Trigger grade recompute for all affected students
  triggerGradeRecompute(assessment.class_id)

  LOG educator activity: event_type = ASSESSMENT_DELETED
```
