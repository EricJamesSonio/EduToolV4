# DEV-04 — Educator Management
**EduTool Developer Guide**
> Covers: Educator accounts, class assignments, mid-semester reassignment, educator removal, ownership history log.

---

## 1. Overview

Educators are scoped entirely to their assigned classes. They cannot see other educators' classes, cannot modify student profiles or enrollments, and cannot change org structure. Admin controls all of this. This guide covers the Admin-side management of educator accounts and their class assignments.

---

## 2. Educator Data Model

```
Educator
  id              UUID, primary key
  user_id         FK → User (role = EDUCATOR)
  org_id          FK → Organization
  educator_code   string, unique within org
                  format: EDU-{XXXX}, e.g. "EDU-4821"
  created_at      timestamp
```

See DEV-02 for account creation.

---

## 3. Educator Search

Admin can search educators by:
- `educator_code` (exact or partial match)
- `full_name` via `User.full_name` (case-insensitive partial)

Results show: Full Name, Educator Code, Email, number of active classes.

---

## 4. Educator Detail View (Admin)

From the educator detail view, Admin can:

1. View profile (name, email, educator code)
2. View all classes currently assigned to this educator (name, subject, semester, school year, student count)
3. Add a class assignment (see Section 5)
4. Remove a class assignment (see Section 6)
5. Reset password (see DEV-02 Section 5)

---

## 5. Adding a Class Assignment

When Admin wants to assign an existing class to an educator (not creating a new class — that is handled in DEV-05).

```
Step 1  Admin opens educator detail view.
Step 2  Admin clicks "Assign Class".
Step 3  Admin searches for a class by title, subject, semester, school year.
        Only classes within the same org are shown.
        Classes already assigned to this educator are excluded from results.
Step 4  Admin selects the class.
Step 5  System checks:
          [ ] Class is not archived
          [ ] Class does not already have this educator assigned
          [ ] Reassignment conflict: if class already has another educator,
              treat this as a reassignment (see Section 7 below)
Step 6  Admin confirms.
Step 7  Update class.educator_id = this educator.
Step 8  Notify new educator: "You have been assigned to class [Title]."
Step 9  Log in Admin Audit Log:
          action_type = "EDUCATOR_CLASS_ASSIGNED"
          details = { educator_id, class_id, admin_id }
```

---

## 6. Removing a Class Assignment

Admin can remove an educator's class assignment. This triggers the reassignment flow if the class is still active.

```
Step 1  Admin opens educator detail view.
Step 2  Admin selects a class to remove from this educator.
Step 3  System checks:
          is_active = class is not archived AND semester is currently running
        IF is_active:
          Warn Admin: "This class is currently active. You must assign a
            replacement educator before removing [Educator Name]."
          Force Admin to select a new educator before proceeding.
          → This becomes a Reassignment (see Section 7).
        IF not active (archived or semester hasn't started):
          Admin confirms removal.
          class.educator_id = null (or leave as-is for archived classes)
          Log in Admin Audit Log.
```

---

## 7. Mid-Semester Reassignment

When an active class's educator is changed at any time (whether initiated from the educator detail view or the class detail view).

### 7.1 What Transfers to the New Educator

The new educator takes ownership of everything in the class:

| Transferred | Notes |
|---|---|
| All lessons and concept builds | Fully accessible to new educator |
| All assessments | Including generated questions, published and unpublished |
| Grading responsibilities | Including ungraded essays |
| Unpublished scores | New educator can publish or withhold |
| Attendance records | Full history, new educator can edit going forward |

### 7.2 Historical Attribution — Never Changes

Scores and grades already recorded by the previous educator **remain attributed to them.** The system stores `graded_by_educator_id` on each score record. This is never modified retroactively.

```
GradeRecord
  id                    UUID
  class_id              FK → Class
  student_id            FK → Student
  assessment_id         FK → Assessment
  score                 decimal
  graded_by_educator_id FK → Educator  -- set at time of grading, never changes
  graded_at             timestamp
```

### 7.3 Ownership History Log

Every reassignment creates an immutable log entry:

```
ClassOwnershipLog
  id                  UUID, primary key
  class_id            FK → Class
  previous_educator_id  FK → Educator
  previous_educator_from  timestamp  -- when they were assigned
  previous_educator_to    timestamp  -- now (time of reassignment)
  new_educator_id     FK → Educator
  new_educator_from   timestamp  -- now
  reason              string, nullable (optional Admin note)
  created_by_admin_id FK → User (role = ADMIN)
  created_at          timestamp
```

Rules:
- Never delete these records. They are permanent.
- Never update them. Each reassignment creates a new row.
- Visible to Admin only. Educators do not see this log.

### 7.4 Reassignment Flow

```
Step 1  Admin initiates reassignment (from educator detail or class detail).
Step 2  Admin selects the replacement educator.
Step 3  Admin optionally enters a reason (free text, max 500 chars).
Step 4  System confirms:
          "Reassign class [Title] from [Old Educator] to [New Educator]?
           All lessons, assessments, and grades will transfer. Confirm?"
Step 5  Admin confirms.
Step 6  Create ClassOwnershipLog entry.
Step 7  Update class.educator_id = new_educator.id
Step 8  Notify new educator: "You have been assigned to class [Title]."
Step 9  Log in Admin Audit Log:
          action_type = "EDUCATOR_CLASS_REASSIGNED"
          details = { class_id, from_educator_id, to_educator_id,
                      reason, admin_id }
```

---

## 8. Educator Removal

Admin can remove an educator account from the org entirely.

### 8.1 Rules

- **Blocked** if the educator has any active class assignments.
- Admin must reassign all active classes first (Section 7).
- Once no active classes remain, removal proceeds.
- Archived classes retain the educator record for attribution — the educator account becomes inactive but is **never deleted from the database.**

### 8.2 Flow

```
Step 1  Admin opens educator detail view.
Step 2  Admin clicks "Remove Educator".
Step 3  System checks:
          active_classes = classes where educator_id = this educator
                           AND is_archived = false
          IF active_classes.length > 0:
            Block removal. Show: "This educator has [N] active class(es).
              Reassign all classes before removing this account."
            Show list of active classes with reassign buttons.
            STOP.
Step 4  No active classes. Admin confirms removal.
Step 5  Set user.is_active = false (soft disable — never hard delete).
        Educator cannot log in.
        All historical records (ClassOwnershipLog, GradeRecord.graded_by,
        archived class references) remain intact.
Step 6  Log in Admin Audit Log:
          action_type = "EDUCATOR_REMOVED"
          details = { educator_id, admin_id }
```

---

## 9. Educator Activity Log

Every educator has a log of class-level events scoped to their assigned classes. Educators see only their own log. Admin can see all educator logs.

```
EducatorActivityLog
  id              UUID, primary key
  educator_id     FK → Educator
  class_id        FK → Class
  event_type      enum (see below)
  details         JSON
  created_at      timestamp
```

**Logged event types:**

| Event Type | Triggered When |
|---|---|
| `STUDENT_ENROLLED` | New student added to class (auto or by Admin) |
| `STUDENT_REMOVED` | Student removed from class (by educator or Admin) |
| `MEETING_STARTED` | Educator opens meeting room |
| `MEETING_ENDED` | Educator ends meeting |
| `ASSESSMENT_CREATED` | New assessment configured |
| `ASSESSMENT_EDITED` | Assessment questions edited |
| `ASSESSMENT_PUBLISHED` | Scores published (all or selected) |
| `ASSESSMENT_UNPUBLISHED` | Scores hidden |
| `ASSESSMENT_DELETED` | Assessment soft-deleted |
| `GRADES_LOCKED` | Grade lock applied (manual or auto) |
| `LESSON_CREATED` | New lesson saved |
| `LESSON_UPDATED` | Existing lesson content changed |
| `CONCEPT_EXTRACTION_TRIGGERED` | Manual re-extraction started |
| `CONCEPT_EXTRACTION_COMPLETED` | Background job finished |
