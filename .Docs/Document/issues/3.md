4. Academic Calendar (Optional but Recommended)
Purpose

Schools often have:

holidays

suspension days

exam weeks

special academic events

These affect lessons, attendance, and meetings.

New Admin Feature

Organization Academic Calendar

Calendar Event Types:

Event Type	Effect
Holiday	Classes do not meet
No Class Day	Sessions skipped
Exam Week	Advisory only
Special Event	Informational
System Behavior

When a class session falls on a calendar event:

attendance session is skipped

lesson scheduling adjusts automatically

meeting reminders suppressed

Why this matters

Without this feature, teachers must manually adjust schedules during holidays.

5. Assessment Attempt Control
Purpose

Prevent cheating and submission conflicts.

Rule

Each student may have only one active assessment attempt.

Behavior

When a student opens an assessment:

assessment attempt created
status = active

If another session tries to open the same assessment:

system resumes existing attempt
Benefits

Prevents:

multiple tab attempts

multiple device attempts

accidental duplicate submissions    

6. Educator Reassignment Behavior

When a class educator is reassigned mid-semester, responsibilities transfer fully to the new educator.

Transfer Rules

The new educator inherits:

all lessons

concept builds

assessments

grading responsibilities

unpublished scores

attendance records

Historical Attribution

Scores remain attributed to the educator who graded them.

Example:

Quiz graded by:
Prof. Santos (original educator)

Even if reassigned later.

Why this matters

Ensures continuity of academic responsibility.

7. Notification Retention Policy

Current notification system is intentionally simple.

However, long-running institutions may accumulate thousands of notifications.

Recommended Retention Rule

Notifications older than 90 days are archived.

Archived notifications:

removed from active list

stored for internal logs only

Optional Future Enhancement

Assessments

8. Soft Delete for Critical Records

EduTool currently states that historical data is never deleted.

To ensure system safety, critical records should use soft deletion.

Soft Delete Applies To

classes

assessments

lessons

enrollments

meetings

Implementation Concept

Instead of deleting records:

deleted_at timestamp

Records become invisible in UI but remain in the database.

Why this matters

Protects against accidental destructive actions.
