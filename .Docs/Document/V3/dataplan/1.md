**PATTERN 1 — Subject scoping (open vs. course-coupled)**

Right now your `Subject` model has no `course_id`. You need to add it as nullable. If `course_id` is null, the subject is open — any course can use it (minors, gen ed). If `course_id` is set, it belongs exclusively to that course.

You also need a `Course` model separate from what you have. Currently your schema has no course table at all — courses likely live in `metadata` or are implicit. You need:

```prisma
model Course {
  id         String  @id @default(uuid())
  org_id     String
  program_id String  // links to the College/SHS program
  name       String  // e.g. "BSCS", "BSTM", "BSED"
  code       String? // optional short code
}

model Strand {
  id         String @id @default(uuid())
  org_id     String
  program_id String
  name       String // e.g. "STEM", "ABM", "HUMSS"
}
```

Then on `Subject`:

```prisma
model Subject {
  id          String   @id @default(uuid())
  org_id      String
  name        String
  level_id    String
  course_id   String?  // NULL = open/minor, set = course-coupled major
  strand_id   String?  // for SHS strands if needed
  educator_id String?
  is_locked   Boolean  @default(false)
  term_label  String?  // e.g. "1st Year, 1st Sem" for display/seeding reference
  year_level  String?  // e.g. "1st Year", "Grade 11"
}
```

**PATTERN 2 — Prerequisites**

You need a self-referencing join table on subjects:

```prisma
model SubjectPrerequisite {
  id              String @id @default(uuid())
  org_id          String
  subject_id      String  // the subject being enrolled into
  prerequisite_id String  // the subject that must be passed first

  subject      Subject @relation("SubjectPrereqs", fields: [subject_id], references: [id])
  prerequisite Subject @relation("PrereqFor", fields: [prerequisite_id], references: [id])

  @@unique([subject_id, prerequisite_id])
}
```

And on `Subject` add both relation ends:

```prisma
prerequisites SubjectPrerequisite[] @relation("SubjectPrereqs")
prereqFor     SubjectPrerequisite[] @relation("PrereqFor")
```

**Enrollment validation logic** (in your service, not the schema):

When Admin tries to enroll a student in subject X:
1. Fetch all `SubjectPrerequisite` rows where `subject_id = X`
2. For each `prerequisite_id`, check if the student has a `Grade` record where `class.subject_id = prerequisite_id` AND `is_locked = true` AND the grade value is passing
3. If any prerequisite is unmet → block enrollment, return which prereqs are missing

**PATTERN 3 — Seeding format**

The seed templates live outside the DB (in JSON/code as the spec says). Here's the format you need for a course seed entry:

```typescript
// types for seeding
interface SubjectSeed {
  name: string
  year_level: string       // e.g. "1st Year"
  term_label: string       // e.g. "1st Sem"
  scope: "open" | "course" // open = minor/gen ed, course = major
  course_code?: string     // only if scope = "course", e.g. "BSTM"
  prerequisites: string[]  // subject names that must be passed first
}

interface CourseSeed {
  name: string             // e.g. "BS Tourism Management"
  code: string             // e.g. "BSTM"
  program_type: string     // "college"
  subjects: SubjectSeed[]
}

interface ProgramSeed {
  name: string             // e.g. "College"
  type: string             // "college"
  courses: CourseSeed[]
  open_subjects: SubjectSeed[]  // minors/gen ed shared across all courses
}
```

**PATTERN 4 — Seeding flow when Admin creates org**

The selection cascade in the frontend:

```
Admin selects: College program
  → System shows available courses: [BSCS] [BSTM] [BSED] [BSED-Math]...
  → Admin selects: BSCS + BSTM (unchecks BSED)

  → Open/minor subjects shown: always visible, always selectable
  → BSCS major subjects: shown because BSCS selected
  → BSTM major subjects: shown because BSTM selected
  → BSED major subjects: hidden because BSED not selected
```

When Admin confirms, the seeder:
1. Creates `Course` records for each selected course
2. Creates `Subject` records — open subjects with `course_id = null`, coupled subjects with `course_id = <that course's id>`
3. Creates `SubjectPrerequisite` records by resolving subject names to their new IDs within the same org
4. Links everything with `org_id`

The prerequisite resolution step is why you seed subjects first, then prerequisites in a second pass — you need the IDs to exist before you can link them.
