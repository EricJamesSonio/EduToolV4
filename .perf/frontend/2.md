## 2. Important issue: authentication initialization

In `AuthContext.tsx`, these run independently:

- `bootstrap()` initializes or restores authentication.
- `useAuthProfile()` runs a profile query when a token exists.
- `login()` explicitly fetches the profile through `queryClient.fetchQuery()`.

The profile query may reuse cached data, so this does **not prove** duplicate network requests occur. However, bootstrap and profile fetching overlap enough to warrant investigation.

I would not rewrite this flow yet. An incorrect change could cause login redirects to happen prematurely, authentication state to flicker, or refresh-token recovery to fail.

## 3. Important issue: the Agora bundle

This import is a strong optimization candidate:

```tsx
import AgoraRTC from "agora-rtc-sdk-ng";
```

Because it is a static import, the SDK becomes a dependency of the module that uses it, even though the effect returns early when the meeting credentials are empty.

The safest approach is to load the SDK dynamically when a valid meeting session is initialized. However, the implementation must also handle:

- A user leaving before initialization finishes.
- React Strict Mode and effect cleanup.
- Microphone and camera tracks being created asynchronously.
- Screen-sharing cleanup.
- Rejoining a meeting without leaving stale tracks or listeners.

**I recommend treating this as a dedicated change rather than making a quick import replacement.** The current hook has asynchronous resource initialization, so careless lazy loading could introduce camera or microphone leaks.
